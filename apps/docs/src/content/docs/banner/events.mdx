The banner script reports what visitors do with the banner to `POST /v1/events`. GoPayLocal turns those events into daily counts per campaign and country, which the Analytics page of the dashboard shows.

## Event Types

| Event | Sent when | Stored |
|---|---|---|
| `impression` | The banner is shown | Yes: impressions |
| `click` | The visitor clicks the button | Yes: clicks |
| `copy` | The coupon code is copied | Yes: copies |
| `dismiss` | The visitor closes the banner | No (accepted and ignored) |

**Redemptions** (a GoPayLocal code used at checkout) are counted only from your payment provider's webhooks, never from the browser. A `redemption` event sent to `/v1/events` gets the same `204` response but is ignored, so nobody can inflate your redemption numbers from a web page.

Events are never counted as [API calls](/api/banner/#what-counts-as-an-api-call).

## How Events Are Sent

Each event is one small JSON body, sent as `text/plain` so it needs no CORS preflight. The script uses [`navigator.sendBeacon()`](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/sendBeacon), and falls back to a `keepalive` fetch when the browser refuses the beacon. Sending never delays or breaks the page.

```json
{
  "key": "gpl_pk_0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
  "event": "copy",
  "url": "https://example.com/pricing",
  "campaignId": "01JD8Z5K2R7W",
  "countryCode": "IN",
  "code": "PPP-IN30-K7QX"
}
```

| Field | Required | Description |
|---|---|---|
| `key` | Yes | The public API key |
| `event` | Yes | `impression`, `click`, `copy` or `dismiss` |
| `campaignId` | For storage | The `campaignId` from the config response (during an A/B test, the visitor's arm) |
| `countryCode` | For storage | The `country` from the config response (two letters) |
| `url` | No | The page URL. Accepted, not stored. |
| `code` | No | The copied coupon code (`copy` events). Accepted, not stored. |

The endpoint answers `204 No Content` when the key is valid. An event is dropped silently (the response is still `204`) when its campaign does not belong to the key's organization or its country code is not two letters, so a public key cannot be used to write into someone else's analytics. An unknown key gets `401`, a malformed body `400`.

The endpoint is rate limited per IP address and per key; a site at the Pro fair-use level stays far below the per-key limit.

## Session Caching

The banner script reuses a config response that has a discount from `sessionStorage` for 5 minutes, so moving between pages does not repeat the request. See [Installation](/banner/installation/) for the script tag options, including turning browser storage off.

## Analytics Dashboard

The Analytics page shows totals and breakdowns by country and by campaign:

- **Impressions**: visitors who saw the banner
- **Clicks**: visitors who clicked its button
- **Copies**: visitors who copied the code
- **Redemptions**: codes used at checkout, from your payment provider

How far back you can look depends on the plan: 7 days on Free, 365 days on Pro, no limit when self-hosted. The same numbers are available from the [Analytics API](/api/analytics/).

## Privacy

What the banner keeps in the visitor's browser:

- No cookies.
- `sessionStorage`: the cached config response (cleared when the tab closes).
- `localStorage`: a random visitor ID (`gpl_vid`), used only to keep the visitor in the same A/B test arm. The `data-no-storage` script option turns all browser storage off; A/B arms then follow the IP address and user agent instead.

What GoPayLocal does with the request:

- The IP address is used while answering, for the country lookup, VPN detection, rate limiting and (without a visitor ID) A/B arm assignment. GoPayLocal does not write IP addresses, visitor IDs or page URLs to its database.
- Stored analytics are counts per day, campaign and country only.
